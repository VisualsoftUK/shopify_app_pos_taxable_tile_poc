# i18n

## Overview

The package ships 13 JSON locale files (`en`, `de`, `es`, `fi`, `fr`, `is`, `it`, `ja`, `nl`, `no`, `pl`, `pt`, `sv`) loaded via `loadJsonTranslationsFrom`. On the JS side, `createI18nInstance` merges package translations with app translations so both namespaces are available.

## Vite alias requirements

Add these to the consuming app's `vite.config.js`:

```js
resolve: {
    alias: {
        '@admin':        '/path/to/vendor/visualsoft/vs-shopify-admin/resources/js/src',
        '@admin-css':    '/path/to/vendor/visualsoft/vs-shopify-admin/resources/css',
        '@admin-locales': '/path/to/vendor/visualsoft/vs-shopify-admin/locales',
        // also required for other package deps:
        '@mantle-locales': '/path/to/vendor/visualsoft/vs-mantle/locales',
        '@app-pricing-locales': '/path/to/vendor/visualsoft/vs-shopify-app-pricing/locales',
    },
}
```

## `createI18nInstance`

```js
import { createI18nInstance } from '@admin/Services/Common/I18n';

const i18n = createI18nInstance(i18nextModule, loadAppTranslations);
```

- `i18nextModule` — the `i18next` module (passed in to allow SSR/test isolation).
- `loadAppTranslations` — optional async function `(locale: string) => object` that returns the consuming app's translation keys. Merged on top of package translations at runtime.
- Merges Polaris + Mantle + App Pricing + admin translations automatically; app translations take highest priority.

## `useLocale`

```js
import { useLocale } from '@admin/Services/Common/I18n';

const { t, locale, setLocale } = useLocale(loadAppTranslations);
```

- `loadAppTranslations` — same optional async loader. Pass `null` if the app has no extra translations.
- Returns `t` (translation function), `locale` (current locale string), and `setLocale` (setter).

## `I18nProvider`

Wrap the app's React tree with `I18nProvider` to make the i18n instance available via context:

```jsx
import I18nProvider from '@admin/Components/Common/I18nProvider';

<I18nProvider i18n={i18n}>
    <App />
</I18nProvider>
```

## `TranslationProvider` / `LanguageSelector`

- `TranslationProvider` — context provider for the translation loader. Used internally by `useLocale`.
- `LanguageSelector` — UI component for switching locale. Calls `setLocale` internally.

## Translation merge layers (lowest → highest priority)

1. Polaris locale bundle
2. Mantle locale bundle (`@mantle-locales`)
3. App Pricing locale bundle (`@app-pricing-locales`)
4. Package admin locale bundle (`@admin-locales`)
5. Consuming app translations (via `loadAppTranslations`)

## Adding app-level translation keys

App translations (layer 5 — highest priority) are loaded via `loadAppTranslations`. To add keys specific to the consuming app:

1. Create a JSON file per locale in your app (e.g. `resources/js/locales/en.json`, `de.json`, etc.).
2. Register each locale with a dynamic import in `LOCALE_CONFIG`:

```js
const LOCALE_CONFIG = {
    en: () => import('./locales/en.json'),
    de: () => import('./locales/de.json'),
    // one entry per supported locale
};
```

3. Pass `LOCALE_CONFIG` to `createAppTranslationLoader`, then to `createI18nInstance`.

**Supported locales** — the package ships: `en`, `de`, `es`, `fi`, `fr`, `is`, `it`, `ja`, `nl`, `no`, `pl`, `pt`, `sv`. Only add locale files for locales your app actually supports; missing locales fall back to `en`.

**Key namespacing** — app keys are merged on top of package keys, so you can override a package string by using the same key path. Use a distinct top-level namespace (e.g. `"myApp": { ... }`) to avoid accidental overrides.

## Initialisation pattern (from `Initialisation.jsx`)

```jsx
import { createI18nInstance } from '@admin/Services/Common/I18n';
import { createAppTranslationLoader } from '@admin/Services/Common/TranslationProvider';

const loadAppTranslations = createAppTranslationLoader(LOCALE_CONFIG);
const i18n = createI18nInstance(i18n, loadAppTranslations);
```

`LOCALE_CONFIG` is an object mapping locale codes to dynamic imports of the consuming app's JSON files.
